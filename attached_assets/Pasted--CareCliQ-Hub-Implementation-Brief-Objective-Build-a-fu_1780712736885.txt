# CareCliQ Hub Implementation Brief

## Objective

Build a fully functional front-end prototype of the new CareCliQ Hub that acts as the organizational landing experience after login.

This implementation is intended to demonstrate the future direction of CareCliQ as an Organizational Intelligence Platform.

The Hub must coexist alongside the existing CareCliQ platform and must not modify any existing workspace functionality.

---

## Critical Constraints

### DO NOT MODIFY

Under no circumstances should you modify:

* Existing authentication logic
* Existing user roles
* Existing database schema
* Existing API endpoints
* Existing backend services
* Existing Supabase tables
* Existing session management workflows
* Existing participant management workflows
* Existing support worker workspace functionality
* Existing support coordinator workspace functionality
* Existing clinician workspace functionality
* Existing compliance engine functionality
* Existing AI suggestion functionality
* Existing navigation structures currently used by workspaces

The current CareCliQ system is considered production functionality.

The Hub must be additive only.

---

## Build Strategy

Create the Hub as a completely isolated feature layer.

Think of it as:

Login
→ CareCliQ Hub
→ Existing Workspace

The Hub should consume existing data where available.

Where data is unavailable, use realistic mock data.

No backend changes are required.

No migrations are required.

No new services are required.

No API contract changes are required.

---

## New Route

Create a completely new route:

/hub

Examples:

/hub
/hub/overview

The Hub must not replace existing routes.

The Hub must not become the default landing page.

We are currently evaluating the concept.

## Validation Checklist

Before completing implementation verify:

* No backend files modified
* No database migrations created
* No API changes introduced
* No authentication changes introduced
* No existing workspace routes modified
* No participant functionality altered
* No session functionality altered
* No compliance engine functionality altered

The final result must be a completely isolated Organizational Hub prototype that demonstrates the future CareCliQ vision while preserving all current production functionality.

Success means the Hub can be removed tomorrow and the existing platform continues functioning exactly as it does today.
