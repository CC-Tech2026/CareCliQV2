# GCP API Key Exposed in Mobile Configuration File

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-08-25 06:10:38 UTC
**Target:** /workspace/CareCliQV2/artifacts/mobile/google-services.json
**Endpoint:** artifacts/mobile/google-services.json
**CWE:** CWE-798
**CVSS:** 6.5
**Fix Effort:** Low

## Description

A Google Cloud Platform (GCP) API key for the Firebase project `carecliq-13c18` is hardcoded in the `google-services.json` configuration file within the repository. While validation confirms most GCP APIs are currently disabled for this key, it remains active and could be leveraged if APIs are enabled or for quota exhaustion attacks.

## Impact

An attacker with access to the exposed GCP API key can:

- **Quota exhaustion**: Make unlimited API requests to exhaust project quotas and cause denial of service
- **Cost exploitation**: If billing is enabled and APIs are activated, generate significant GCP usage costs
- **Service enumeration**: Probe which GCP/Firebase services are enabled for the project
- **Firebase access**: Potentially access Firebase Dynamic Links, Cloud Messaging, or other Firebase-specific services
- **Future risk**: If Translation API, Speech-to-Text, or other services are later enabled, the exposed key immediately grants access

While current impact is limited (most APIs returned 403 "not enabled"), the key is **active and valid**. The risk escalates significantly if:
1. Additional GCP APIs are enabled for the project
2. The same key gains broader permissions through project configuration changes
3. The key is used across multiple GCP projects (scope expansion)

## Technical Analysis

The `google-services.json` file is a standard Firebase/GCP mobile SDK configuration file that contains API keys and project identifiers:

```json
{
  "project_info": {
    "project_number": "73068767059",
    "project_id": "carecliq-13c18",
    "storage_bucket": "carecliq-13c18.firebasestorage.app"
  },
  "client": [{
    "api_key": [{
      "current_key": "AIzaSyAw2TedpturF3LWtExgC4Duojg6BN4AXRg"
    }]
  }]
}
```

GCP API keys are bearer tokens that authenticate requests to Google Cloud services. Unlike service account keys (JSON credentials with private keys), API keys:
- Are **project-scoped** rather than account-scoped
- Can be **restricted** to specific APIs, HTTP referrers, or IP addresses
- Are typically **less sensitive** than service account keys, but still require protection

Validation testing confirmed:
- **Translation API**: 403 (API not enabled for project 73068767059)
- **Speech-to-Text API**: 403 (API not enabled)  
- **Firebase Dynamic Links**: 403 (requests blocked)

However, the key format is valid and the project exists. The `.env.example` file references these same GCP services:

```bash
# .env.example lines 36-44
GOOGLE_CLOUD_TRANSLATION_API_KEY=
# GCP Console → APIs & Services → enable:
#   1) Cloud Translation API
#   2) Cloud Speech-to-Text API
```

This indicates the application **intends to use** these APIs, suggesting the key may gain permissions in future deployments or if a developer enables the APIs during testing.

## Proof of Concept

1. Extract GCP API key from `artifacts/mobile/google-services.json`
2. Attempt authenticated request to Google Cloud Translation API
3. Observe 403 response indicating API not enabled, but key is valid
4. Demonstrate that the key format is accepted by Google Cloud services

```python
import requests
import json

# Extract from artifacts/mobile/google-services.json
with open("/workspace/CareCliQV2/artifacts/mobile/google-services.json") as f:
    config = json.load(f)
    
GCP_API_KEY = config["client"][0]["api_key"][0]["current_key"]
PROJECT_ID = config["project_info"]["project_id"]
PROJECT_NUMBER = config["project_info"]["project_number"]

print(f"Project ID: {PROJECT_ID}")
print(f"Project Number: {PROJECT_NUMBER}")
print(f"API Key: {GCP_API_KEY}")

# Test key validity against Translation API
url = "https://translation.googleapis.com/language/translate/v2/languages"
params = {"key": GCP_API_KEY, "target": "en"}

response = requests.get(url, params=params, timeout=10)
print(f"\nTranslation API Response: {response.status_code}")

if response.status_code == 403:
    error_data = response.json()
    error_msg = error_data.get("error", {}).get("message", "")
    print(f"Error: {error_msg}")
    
    # 403 with "API not enabled" means key is valid but API disabled
    if "has not been used" in error_msg or "is disabled" in error_msg:
        print("\n✓ Key is VALID (accepted by Google)")
        print("✗ API not currently enabled (limited immediate impact)")
        print("⚠️  Risk escalates if APIs are enabled in future")
    else:
        print("Key may be restricted or invalid")
elif response.status_code == 200:
    print("✓ Key has ACTIVE Translation API access")
else:
    print(f"Unexpected status: {response.status_code}")

# Output demonstrates valid key with APIs disabled:
# Translation API Response: 403
# Error: Cloud Translation API has not been used in project 73068767059 before or it is disabled.
# ✓ Key is VALID (accepted by Google)
# ✗ API not currently enabled (limited immediate impact)  
# ⚠️  Risk escalates if APIs are enabled in future
```

## Remediation

**Immediate (within 24 hours):**

1. **Rotate GCP API key** via GCP Console:
   ```
   GCP Console → APIs & Services → Credentials → 
   Select API key → Regenerate key
   ```

2. **Apply API key restrictions**:
   - **Application restrictions**: Limit to Android app package `care.cliq2026`
   - **API restrictions**: Restrict to only required APIs (Firebase, Translation, Speech-to-Text)
   - **Referrer restrictions**: Add mobile app package fingerprints

3. **Update mobile app configuration**:
   - Replace `google-services.json` with new restricted key
   - Rebuild and redeploy mobile application

**Short-term (within 1 week):**

4. **Remove sensitive config from repository**:
   - Move `google-services.json` to `.gitignore`
   - Store production config in CI/CD secrets or app distribution platform
   - Provide example template with placeholder key:
     ```json
     {
       "api_key": [{"current_key": "YOUR-API-KEY-HERE"}]
     }
     ```

5. **Implement GCP API restrictions**:
   - Enable only required APIs (Translation, Speech-to-Text) with minimal scopes
   - Set up billing alerts to detect abuse
   - Configure quota limits to prevent cost exploitation

6. **Audit GCP project access**:
   - Review IAM permissions for project `carecliq-13c18`
   - Check API key usage logs for unauthorized requests
   - Verify no other API keys are exposed

**Long-term (within 1 month):**

7. **Implement secrets management for mobile**:
   - Use Firebase App Check to restrict API access to legitimate app instances
   - Consider Firebase Remote Config for runtime configuration
   - Implement certificate pinning for mobile API requests

8. **Security scanning**:
   - Add `google-services.json` to `.gitignore` enforcement
   - Scan git history for other GCP/Firebase credentials
   - Implement pre-commit hooks to block credential commits

9. **Developer training**:
   - Document proper handling of `google-services.json`
   - Establish separate development/staging/production GCP projects
   - Never commit production Firebase config to version control

## Assumptions

Assumes attacker discovers the API key through repository access. Current risk is **medium** rather than critical because most GCP APIs are disabled. However, risk escalates to **high** if:
- Translation API or Speech-to-Text API are enabled (as indicated in `.env.example`)
- Key restrictions are not properly configured
- The same key is reused across multiple projects

The key is valid and accepted by Google Cloud services, confirmed by 403 responses indicating API-level restrictions rather than key invalidity.
