# CVE-2024-23342 in ecdsa 0.19.2 (Minerva timing attack vulnerability)

**ID:** vuln-0007
**Severity:** HIGH
**Found:** 2026-08-25 06:18:53 UTC
**Target:** /workspace/CareCliQV2

**Ecosystem:** pypi
**Installed Version:** 0.19.2
**Introduced By:** python-jose@3.5.0
**Dependency Chain:** python-jose@3.5.0 > ecdsa@0.19.2
**CVE:** CVE-2024-23342
**CVSS:** 7.4
**Fix Effort:** Low

## Description

The `ecdsa` package version **0.19.2** is vulnerable to **CVE-2024-23342**, a cryptographic timing attack known as the **Minerva attack**. This pure Python implementation of Elliptic Curve Cryptography exhibits timing side-channels during ECDSA signature operations, potentially allowing attackers to recover private keys through careful timing analysis of signature generation. The advisory notes that **no patched version exists** as of the CVE publication.

## Evidence

**Advisory evidence:** `CVE-2024-23342` applies to `ecdsa` at installed version `0.19.2`.

**Transitive dependency:** introduced by the direct dependency `python-jose@3.5.0`.

**Dependency chain:** `python-jose@3.5.0 > ecdsa@0.19.2`

**Usage analysis:** imported by application code; affected API usage unconfirmed. The `python-jose` library is imported and actively used in `backend/app/core/security.py:3` (`from jose import JWTError, jwt`). JWT operations are performed via `jwt.encode()` and `jwt.decode()` for authentication token generation and validation (lines 25, 30). 

However, the current configuration uses **HS256** algorithm (`backend/app/core/config.py:79`), which is HMAC-based and does not invoke the vulnerable `ecdsa` library. Static analysis confirmed no direct imports of `ecdsa`: `rg "from ecdsa|import ecdsa" --type py -l` returned no results.

The `ecdsa` package is pulled in as a transitive dependency by `python-jose` to support ES256/ES384/ES512 algorithms, but these ECDSA-based algorithms are not currently configured. Reachability classification is `imported` because while the parent library (`python-jose`) is actively used, the specific vulnerable code path (ECDSA signature operations) is not confirmed to be executed with the current HS256 configuration. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

The application uses `python-jose[cryptography]` for JWT token generation and validation (`backend/app/core/security.py`), which transitively depends on the vulnerable `ecdsa` library. While the current JWT configuration uses **HS256 (HMAC-SHA256)** which does not use ECDSA, the vulnerable library is present and could be exploited if:

1. The JWT algorithm is changed to ES256/ES384/ES512 (ECDSA-based algorithms)
2. Other parts of the application use ECDSA for signature operations
3. `python-jose` internally uses ECDSA for certificate validation or other operations

If ECDSA operations are performed, an attacker with the ability to observe signature generation timing (e.g., via network timing, shared infrastructure, or timing side-channels) could potentially recover the ECDSA private key through the Minerva attack, leading to complete cryptographic compromise.

## Remediation

**Immediate:** Verify that no ECDSA-based JWT algorithms (ES256, ES384, ES512) are used in production. Confirm the current **HS256** configuration remains in place and is not user-configurable.

**Medium-term:** Consider migrating from `python-jose` to `PyJWT` which uses the `cryptography` library's constant-time ECDSA implementation instead of the pure-Python `ecdsa` package. This eliminates the timing attack vulnerability.

**Long-term:** Monitor for patched versions of `ecdsa` or upstream fixes in `python-jose` that replace the vulnerable dependency. Implement cryptographic algorithm allowlisting to prevent runtime algorithm changes to ECDSA-based schemes.

## Assumptions

Current exploitation risk is **low** because the application uses HS256 (HMAC) rather than ECDSA-based algorithms for JWT signing. However, the vulnerable library is present in the dependency tree and could be exploited if:

- Configuration changes enable ES256/ES384/ES512 algorithms
- Future code additions use ECDSA signatures  
- `python-jose` uses ECDSA internally for other operations beyond the observed `jwt.encode/decode` calls

The Minerva attack requires the attacker to observe many signature operations and measure precise timing differences, which is challenging but feasible in cloud environments with shared infrastructure or through network timing analysis.
